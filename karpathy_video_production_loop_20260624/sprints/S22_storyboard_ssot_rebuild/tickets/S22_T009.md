# S22_T009 - Add timing/drift contract validator

## Objective

Validate that every shot carries enough timing policy for downstream handling of real provider duration drift.

Software Engineer

## Required behavior

For every canonical shot, require:

- `planned_duration_sec`
- `min_usable_duration_sec`
- `max_usable_duration_sec`
- `duration_drift_policy`
- `assembly_fit_policy`

Allowed `duration_drift_policy` values:

- `trim_ok`
- `pad_ok`
- `extend_still_ok`
- `regenerate_required`
- `sonnet_repair_required`
- `human_review_required`

Validator must also enforce:

- min <= planned <= max
- hero/lipsync shots cannot use weak pad-only policies
- local graphics must state whether extension is allowed
- generated B-roll must state trim behavior

## Detailed tests

Required tests:

1. Complete timing policy passes.
2. Missing planned duration fails.
3. Missing min/max usable duration fails.
4. min greater than planned fails.
5. planned greater than max fails.
6. Unknown drift policy fails.
7. Hero lipsync with `pad_ok` only fails.
8. B-roll missing trim/regen policy fails.
9. Local graphic missing extension policy fails.

Required commands:

```bash
python3 -m pytest tests/test_storyboard_timing_policy.py -q
```

## Pass gates

- Every shot has drift policy before generation.
- Invalid timing policy cannot reach media compile.
- Error messages include shot ID and policy field.

## Audit checklist

- Confirm no actual drift resolution is implemented early.
- Confirm policy names match `S22_FEEDBACK_LOOP_RULES.md`.
- Confirm hero/lipsync is treated strictly.

## Validation checklist

- Run focused tests.
- Inspect fixtures for realistic 4.2s vs 5.1s style cases.

## Done definition

Done when timing drift expectations are validated before spend.
