# S22_T020 - Add downstream invalidation/rerun planner

## Objective

Plan and enforce narrow downstream invalidation after storyboard feedback, media duration drift, compliance failures, or repaired entities.

## Explicit non-goals

- Do not perform actual paid rerenders.
- Do not implement feedback ingestion.
- Do not implement repair generation.

## Required behavior

Given a targeted change request or repaired entity, planner must:

- Identify affected downstream stages.
- Mark affected stage runs stale.
- Mark affected approvals stale.
- Preserve unaffected artifacts and stage runs.
- Block stale artifact reuse if requirement hash changed.
- Emit exact next action list.

## Detailed tests

Required tests:

1. Shot repair stales compile, spend gate, generate for affected unit, QA, assemble, final QA, Gate B.
2. Overlay repair stales overlay render, assemble, final QA, Gate B only.
3. Media artifact drift repair stales QA media, assemble, final QA, Gate B.
4. Storyboard revision change stales storyboard approval and downstream.
5. Unaffected render unit remains valid.
6. Stale artifact reuse is blocked.
7. Planner emits deterministic next actions.
8. Running planner twice is idempotent.

Required commands:

```bash
python3 -m pytest tests/test_downstream_invalidation.py -q
python3 -m pytest tests/e2e/test_feedback_rerun_flow.py tests/e2e/test_s8_projections_resume.py -q
```

## Pass gates

- Invalidation is neither too broad nor too narrow.
- Stale approvals cannot pass.
- Stale artifacts cannot be reused without matching lineage.
- Next action list is actionable.

## Audit checklist

- Confirm existing invalidation primitives are reused.
- Confirm no global reset/rebuild behavior.
- Confirm idempotency.

## Validation checklist

- Run focused/e2e tests.
- Inspect before/after DB stage rows.
- Confirm unaffected assets survive.

## Done definition

Done when feedback can trigger precise downstream reruns without preserving bad state or destroying good state.
