# S22_T018 - Add duration drift resolver

## Objective

Resolve or block discrepancies between planned render-unit duration and observed artifact duration according to Sonnet-authored shot drift policy.

## Primary agent

DB Feedback Engineer

## Supporting agents

- Overlay Timeline Engineer
- Software Engineer
- Software Auditor

## Explicit non-goals

- Do not generate replacement media.
- Do not call Sonnet repair directly.
- Do not alter final assembly unless policy says trim/pad is accepted.

## Required behavior

Resolver inputs:

- render unit required duration
- artifact actual duration
- shot min/max usable duration
- `duration_drift_policy`
- asset type/audio policy

Resolver outputs:

- `accepted`
- `trim_in_assembly`
- `pad_or_extend`
- `regenerate_same_prompt`
- `sonnet_repair_storyboard`
- `human_review_required`
- `reject_unfixable`

Blocking drift must create or route a change request.

## Detailed tests

Required tests:

1. Planned 4.2s, actual 5.1s, B-roll `trim_ok` -> accepted with trim metadata.
2. Planned 4.2s, actual 3.9s, local graphic `extend_still_ok` -> accepted with extension metadata.
3. Planned 4.2s, actual 3.2s, hero lipsync -> blocked repair/regenerate.
4. Actual duration exceeds `max_usable_duration_sec` -> blocking change request.
5. Actual duration below `min_usable_duration_sec` -> blocking change request unless policy allows extension.
6. Missing actual duration -> `BLOCKED_DURATION_DRIFT_UNRESOLVED`.
7. Unknown policy -> block.
8. Accepted trim decision is available to assembly manifest.

Required commands:

```bash
python3 -m pytest tests/test_duration_drift_resolver.py -q
python3 -m pytest tests/test_qa_media.py -q
```

## Pass gates

- Drift is always resolved or blocked.
- Hero/lipsync drift is strict.
- Assembly receives explicit trim/pad instructions.
- Blocking cases create repair route evidence.

## Audit checklist

- Confirm no drift silently passes.
- Confirm resolver does not mutate approved narration.
- Confirm change requests are idempotent.

## Validation checklist

- Run focused tests.
- Inspect resolver output JSON.
- Inspect change request DB rows in test evidence.

## Done definition

Done when provider duration mismatch is a controlled feedback event, not an implicit assembly accident.
