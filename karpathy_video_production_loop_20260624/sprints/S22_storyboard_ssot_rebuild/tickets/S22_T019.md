# S22_T019 - Add compliance feedback ingestion

## Objective

Convert storyboard, media, overlay, and final QA compliance findings into targeted DB feedback/change requests tied to storyboard and render entities.

## Primary agent

DB Feedback Engineer

## Supporting agents

- Claim Compliance Auditor
- Software Engineer
- Software Auditor
- Software Validator

`deepseek-v4-pro`

## Explicit non-goals

- Do not implement rerun planner.
- Do not repair the storyboard.
- Do not regenerate media.

## Required behavior

Feedback ingestion must map findings to:

- entity type
- entity id
- severity
- rule id
- source stage
- finding message
- recommended action
- repair owner
- downstream stages impacted

It must create or update `change_requests`/validation records without duplicating open requests for the same unresolved issue.

## Detailed tests

Required tests:

1. Generic B-roll QA finding creates shot/render-unit change request.
2. Unsupported claim finding creates claim/storyboard change request.
3. Overlay safe-zone finding creates overlay rerender request.
4. Duration drift finding creates render-unit request.
5. Duplicate open finding is idempotent.
6. Finding missing entity id fails `BLOCKED_FEEDBACK_UNROUTED`.
7. Finding missing repair action fails.
8. Minor warning records validation but does not block unless policy says so.

Required commands:

```bash
python3 -m pytest tests/test_feedback_ingestion.py -q
python3 -m pytest tests/e2e/test_crash_matrix.py -q
```

## Pass gates

- Every compliance issue has a target and action.
- Duplicate requests are idempotent.
- No finding disappears as prose-only report text.

## Audit checklist

- Confirm feedback uses existing tables where possible.
- Confirm entity IDs are stable.
- Confirm blocking severity blocks downstream.

## Validation checklist

- Run focused tests.
- Inspect DB evidence rows.

## Done definition

Done when compliance gates can feed targeted repair/rerun decisions.
