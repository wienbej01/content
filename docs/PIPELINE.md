# Production Pipeline - DB-Native Edition

`scripts/produce_db.py` is the active production entry point. It runs a video from seed idea through research, script, Sonnet-authored canonical storyboard, media planning, generation, QA, assembly, review, publish, and analytics using the production ledger as the system of record.

Legacy file-based CLIs still exist as stage implementations or developer tools, but production orchestration should use the DB-native runner.

```bash
python3 scripts/produce_db.py create --seed "topic idea" --format short
python3 scripts/produce_db.py run <production_id>
python3 scripts/produce_db.py resume <production_id>
python3 scripts/produce_db.py run <production_id> --from-stage storyboard
python3 scripts/produce_db.py status <production_id>
```

Formats include `smoke`, `teaser`, `short`, and `explainer`, with spend caps enforced at Gate A spend.

## Stage Graph


Each stage records a `stage_runs` row. Committed creative documents are stored as active `document_revisions`; media work is stored as `render_units`, `provider_jobs`, `artifacts`, `validations`, and `change_requests`.

## Human Gates

The current mandatory approval gates are:

| Gate | Blocks | Approval command |
| --- | --- | --- |
| `gate_a_content` | Storyboard authoring until the reviewed script is accepted | `python3 scripts/produce_db.py approve <production_id> gate_a_content --pass` |
| `gate_storyboard` | TTS until the reviewed storyboard is accepted | `python3 scripts/produce_db.py approve <production_id> gate_storyboard --pass` |
| `gate_a_spend` | Paid media generation until the render plan and estimated spend are accepted | `python3 scripts/produce_db.py approve <production_id> gate_a_spend --pass` |
| `gate_b_review` | Publish until the final deliverable and QA evidence are accepted | `python3 scripts/produce_db.py approve <production_id> gate_b_review --pass` |

`YT_TEST_MODE=1` uses deterministic fixtures and auto-approval behavior where tests require it. Production mode does not silently bypass the human gates.

## Storyboard Method

Production storyboard authoring is now canonical-first:

1. `produce_db.invoke_storyboard` loads the active DB script and segments.
2. `scripts/sonnet_storyboard_wrapper.py` calls Kilo with profile `storyboard_director_sonnet5`.
3. The prompt is `docs/prompts/STORYBOARD_SONNET5_DIRECTOR.md`.
4. Channel bibles under `docs/channel_universe/` are supplied as grounding material.
5. The output must satisfy `schemas/storyboard_v2.schema.json`.
6. `scripts/storyboard_projection.py` projects canonical shots into DB-compatible creative beats while preserving canonical lineage fields.

Python is the orchestrator and validator; Sonnet 5 is the runtime creative storyboard author. Runtime storyboard tasks are intentionally restricted to `kilo/anthropic/claude-sonnet-5` via `configs/llm_models.yaml` and `scripts/llm_call.py`.

Direct real-LLM storyboard smoke command:

```bash
python3 scripts/sonnet_storyboard_wrapper.py \
  --script scripts/sample_script.json \
  --output /tmp/canonical_storyboard_real_llm.json \
  --verbose \
  --timeout 600
```

Validation commands:

```bash
python3 scripts/validate_storyboard_v2.py /tmp/canonical_storyboard_real_llm.json
python3 scripts/storyboard_v2_validator.py /tmp/canonical_storyboard_real_llm.json
python3 scripts/review_storyboard_v2.py /tmp/canonical_storyboard_real_llm.json --dry-run --output /tmp/review.json --verbose
```

## Media Planning And Generation

`compile_media` converts reconciled storyboard beats and measured timing spans into DB render units. Provider-eligible units are determined by `scripts/media_contract.py`, not by ad hoc stage logic.

Important render methods:

| Type | Handling |
| --- | --- |
| `hero_lipsync` | Provider generation with narration slice or provider-audio compensation policy, then lipsync QA. |
| `hero_cutaway` / B-roll | Provider generation if provider-eligible and approved by spend gate. |
| `local_graphic` | No provider submission; generated by `graphics_compositing`. |
| `reused` | No provider submission; zero estimated cost; must be linked to an existing active artifact before generation can complete. |

The reused-footage path is intentionally fail-closed. If a render unit is marked `asset_type=reused` and has no active artifact, `generate_media` blocks with `reused_asset_unlinked` rather than inventing or regenerating the shot.

## QA, Repair, Assembly, Publish

`qa_media` records per-render-unit validation evidence and routes failures to `repair`. `graphics_compositing` creates deterministic local graphic artifacts. `assemble` uses DB render units and artifacts to build the deliverable. `qa_final` validates final-cut evidence. `gate_b_review` requires final review before `publish`, and `analytics` records the post-publish learning loop.
