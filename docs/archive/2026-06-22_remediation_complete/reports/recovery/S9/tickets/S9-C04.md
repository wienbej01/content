## Observable outcome
A storyboard produced by the DB path (`invoke_storyboard`) passes `review_storyboard.py` `_bands_check` for the production's `video_type` — i.e. the hero/b-roll/graphics percentages are within bands — using the **canonical vocabulary** (`hero_lipsync`, `broll_archival`/`broll_environment`/`broll_tactical`/`broll_metaphorical`, `graphic_progressive`/`graphic_title_card`/`kinetic_text`, `still_kenburns`). Every beat carries a `visual_intent`/prompt that downstream generation (S9-C06) can use. Observable by: a test that runs the DB storyboard derivation on a structured fixture script and asserts (a) `review_storyboard` returns no blocking violations, and (b) at least one hero, one b-roll, and one graphic beat exist with non-empty visual intent.

## Evidence and rationale
- **Observed current behavior:** the real `ai_notes_teaser` storyboard had all 4 beats = `talking_head_standard`; the hero/b-roll/graphic mix never materialized; `review_storyboard` would block (hero/broll/graphics bands unsatisfied).
- **Supporting paths:**
  - `scripts/produce_db.py:309-333` — `invoke_storyboard`: builds one beat per segment, `shot_type = _derive_shot_type(seg)`.
  - `scripts/produce_db.py:363-381` — `_derive_shot_type`: reads `seg.get("shot_type")|"kind"` (neither stored), then infers from `seg.get("id")|"label"` role keywords, else falls back to `talking_head_standard`. Returns the **wrong vocabulary** (`talking_head_*`), not the canonical one.
  - `scripts/authoring_service.py:117` — `seg_id = _db._id("seg")` (random id; the writer's role-bearing id is discarded); `:123` stores `label`. `get_script_segments` (`:151-161`) returns `{id,label,text,word_count}` only — **no role, no shot_type, no visual_intent**.
  - `scripts/review_storyboard.py:28-34,88-108` — canonical `VALID_SHOT_TYPES`/`HERO_SHOT_TYPES`; `_bands_check` (explainer: hero 25–40%, hero_lipsync ≤25%, broll_specific ≥25%, graphics_ui ≥10%; short relaxed).
  - `scripts/direct_storyboard.py:105-151` — the **real** canonical storyboard generator (shot_type→model map, durations, graphic contracts). Used by `run_episode.py` LLM chain, **not** by the DB path.
- **Confirmed root cause:** the DB storyboard is a simplified stub that (a) discards segment structure/role, (b) derives shot types in the wrong vocabulary, (c) falls back uniformly to talking-head, and (d) emits no usable visual intent. It does not match the real creative storyboard system.
- **Why necessary:** without a compliant mix, `review_storyboard` blocks (or, if bypassed, generation has no hero/graphic structure and no prompts).

- **Exclusions:** do not change `compile_media` routing logic (it already maps canonical types — `produce_db.py:433-447`); do not change assembly.
- **DESIGN DECISION (resolve before implementing; document the choice in the ticket + commit):**

  - Choose A if `direct_storyboard.py` can run in the DB authoring flow without an external dependency mismatch; choose B if A is too invasive for one session. Either way, the result must pass `review_storyboard` bands and carry visual intent. If A is chosen, S9-C04 may need a companion change in the pre-TTS invoker wiring (`produce_db.py` authoring section).
