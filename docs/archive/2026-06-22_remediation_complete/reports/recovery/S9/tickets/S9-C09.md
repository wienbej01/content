## Evidence and rationale
- **Observed current behavior:** the full suite stalls at `tests/test_research_sources.py::test_reputable_sorted_first` (and would at peers) with a `subprocess.communicate` timeout. The test calls `research("test topic", dry_run=False)`; it mocks `research.brave_search` but **not** the LLM call, so `research()` reaches `scripts/research.py:262-266` and runs `kiro-cli chat --no-interactive ...` as a real subprocess. When `kiro-cli` is unavailable/slow (as in this environment), that subprocess never returns. `pytest.ini` sets `timeout_method = thread`, and a thread timeout **cannot kill** a hung subprocess, so the entire suite stalls (no recovery, no summary) — `PYTEST_EXIT=1`.
- **Supporting paths:**
  - `scripts/research.py:254-266` — `dry_run=True` returns safely at `:254-255` **before** the subprocess; `dry_run=False` proceeds to `cmd = [KIRO, "chat", ...]; subprocess.run(cmd, ..., timeout=timeout)` at `:262-266`. There is **no `YT_TEST_MODE` guard** here (contrast with the D-013 guard added to `invoke_tts`, `produce_db.py:217-221`, which refuses paid calls in test mode).
  - `tests/test_research_sources.py:44,78,105` — three `research(..., dry_run=False)` calls; they mock `brave_search` only.
  - `pytest.ini` — `timeout = 300`, `timeout_method = thread`.
- **Pre-existing, not a regression:** the stall reproduces at clean baseline `3f1c9fa` with S9-C01's changes stashed (verified). The baseline full suite at session start passed only because `kiro-cli` was responsive then; the suite is non-hermetic and environmentally flaky.
- **Why necessary:** every S9-C ticket's acceptance gate requires "full suite green." This defect makes that gate un-demonstrable whenever `kiro-cli` is down. It also violates the spirit of D-013 (no uncontrolled external/paid calls from tests).
- **Directive alignment:** the user requires "no mock where real test is possible." These tests' *intent* (sorting, capping, prompt content, query expansion) is verifiable by calling the **real** pure functions (`_is_reputable`, the sort at `research.py:250-252`, `build_research_prompt`, query-building) directly with fixture data — a *more* real test of the logic under test, with **no mock and no external call**. That is the preferred fix (not mocking `kiro-cli`).
