## Observable outcome
A script whose estimated narration duration exceeds the active format's `target_sec_range` is **rejected by a deterministic gate** (raises / forces a revision) in the script-writing and script-review stages — not merely requested via prompt text. The `teaser` format's `word_range` is recalibrated so that a within-budget script actually narrates within `target_sec_range` at the real James voice pace (~60–74 wpm). Observable by: a regression test that feeds an over-budget script and asserts the gate fails; a unit test that asserts the teaser word_range is consistent with its target_sec at the calibrated pace.

## Evidence and rationale
- **Observed current behavior:** the real run's `write_script` produced a 195-word script for the `ai_notes_teaser` teaser (target 75 s). At ~60–74 wpm that narrates to ~198 s (2.6× over). `review_script` (LLM `review_loop`) nonetheless passed it.
- **Supporting paths:**
  - `scripts/episode_format.py:34-41` — `teaser.word_range=[140,230]`, `target_sec=75`, `target_sec_range=[50,100]`. At 60–74 wpm, 140–230 words = 113–230 s — the budget and the duration target disagree.
  - `scripts/episode_format.py:49-60` — `format_block()` injects the budget/duration into prompts (soft guidance only).
  - `scripts/write_script.py:52,68` and `scripts/review.py:75-76` — consume `format_block` (prompt-level only).
  - `scripts/produce_db.py:77-106` — `invoke_write_script` saves the writer's output verbatim; **no word/duration validation**.
  - `scripts/produce_db.py:109-155` — `invoke_review_script` runs `review_loop` then saves the final script; **no programmatic check**.
  - `scripts/authoring_service.py:113-126` — `save_script` computes `word_count` per segment (source of truth for the count).
- **Confirmed root cause:** the budget lives only in prompt text; there is no deterministic gate, and the teaser numeric budget is wrong for this voice.
- **Why necessary:** the user explicitly demanded duration compliance; without a programmatic gate the LLM will keep producing over-length scripts.

## Implementation steps
1. **Reproduce (failing test first).** Add a test that builds a 195-word teaser script payload and asserts the duration gate rejects it (and that a ~80-word teaser passes). Run it; it must fail against current code.
2. **Calibrate pace.** Measure words/sec from a real narration artifact (or use 60 wpm). Add `JAMES_VOICE_WPM` (or `NARRATION_WPM`) constant in `episode_format.py` with a comment citing the measurement source and date.
3. **Recalibrate teaser budget.** Set `teaser.word_range` to the range consistent with `target_sec_range` at the calibrated pace (e.g. ~[75, 95] for 50–100 s @ ~60 wpm; compute, don't hand-wave). Keep `target_sec`/`target_sec_range` as the authority; consider deriving `word_range` from them so they can't drift again.
4. **Add the gate helper.** In `episode_format.py` add `estimate_duration_sec(word_count, video_type)` and `script_within_budget(script_payload, video_type)` (sums segment `word_count`, compares to `target_sec_range`). Fail-closed on unknown format.
5. **Wire into `invoke_write_script`** (`produce_db.py:77`): after `write_script` returns, if `not script_within_budget(data, video_type)`, raise a loud `RuntimeError` naming the actual vs allowed word/duration range (do not save). 
6. **Wire into `invoke_review_script`** (`produce_db.py:109`): the reviser loop must treat an over-budget `final` as not-passed (either by checking before save and looping the reviser with an explicit "shorten to N words" fix, or by failing the stage). Ensure a compliant script still saves and the stage can succeed.
7. **Keep prompt guidance.** Leave `format_block` injecting the (now-correct) budget into prompts.
8. **Negative path:** ensure the gate message is actionable (state words, estimated seconds, allowed range) so a human/dev can act.
