# Storyboard SSOT sprint plan for `wienbej01/content`

Scope: repo audit + sprint plan only, per the uploaded instruction brief. No implementation, PR, or media generation. 

## A. Executive diagnosis

The current system has a “storyboard” artifact, but not a true storyboarding layer. It mostly converts script segments into compliant production slots. That is useful plumbing, but it is not creative direction. The pipeline is currently optimizing for “not breaking constraints” rather than “making the viewer understand, care, and keep watching.”

The blunt diagnosis: the system is trying to automate editorial taste with Python defaults. That is how you get well-structured mediocrity at scale.

The most important failure points are:

| Hypothesis                                                                  |   Verdict | Repo evidence                                                                                                                                                                                             |
| --------------------------------------------------------------------------- | --------: | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Storyboard generation is deterministic/index-based.                      | Confirmed | `storyboard.py` states “No LLM calls” and “deterministic rule-based defaults,” then classifies first/last segments as A-roll, every third middle segment as James-present, and everything else as B-roll. |
| 2. LLM optimization is shallow.                                             | Confirmed | The LLM pass only optimizes `scene_type` and `james_presence`; it does not design B-roll, overlays, evidence visuals, insert shots, or edit rhythm.                                                       |
| 3. Script `visual_brief` is carrying too much visual responsibility.        | Confirmed | `generate_media.py` still validates that every script segment has `visual_brief`, builds prompts from it, and documents the pipeline as `script.json → generate_media.py`.                                |
| 4. B-roll is not semantically tied to the argument.                         | Confirmed | The prompt compiler builds prompts from “Scene illustrating: [first 100 chars of narration]” plus generic location/lighting/palette. That is a prompt wrapper, not visual reasoning.                      |
| 5. Graphics are not a first-class overlay timeline.                         | Confirmed | `assemble.py` supports a fixed lower-third image path and fades, but not timed overlay events for key points, source labels, framework diagrams, comparisons, or callouts.                                |
| 6. Media prompt compilation consumes limited beat fields.                   | Confirmed | `compile_media_prompts.py` consumes storyboard beats, but the fields are too shallow: `scene_type`, location, lighting, movement, palette, narration excerpt.                                             |
| 7. Assembly is segment/shot concatenation, not editorial timeline assembly. | Confirmed | Assembly can concatenate multi-shot beds and overlay narration, but there is no generalized overlay timeline.                                                                                             |
| 8. Current artifacts are too A-roll/generic B-roll heavy.                   | Confirmed | `teaser_02` uses several baked-in James segments and generic office/city/abstract b-roll; no overlay grammar or evidence reinforcement exists.                                                            |
| 9. Database is not storyboard-aware.                                        | Confirmed | SQLite only models `content_units` and `unit_segments`; no beats, claims, overlays, assets, generation jobs, review outcomes, QA, or feedback loops.                                                      |
| 10. Review gates do not force visual justification.                         | Confirmed | `review_storyboard.py` checks presence, scene type, crop safety, audio continuity, and all-B-roll, but not narrative alignment or overlay purpose.                                                        |
| 11. Python/LLM split is wrong.                                              | Confirmed | Python is making crude creative choices; the LLM is only allowed to tweak broad placement. The repo’s own roadmap notes this was a compliance floor, not retention-driven creative direction.             |

## C. Current storyboard/data model audit

There are currently two different “storyboard-ish” objects:

1. `scripts/storyboard.py` output: beat-level draft storyboard with `beat_id`, `scene_type`, `james_presence`, location, camera, duration, crop safety, and text policy.
2. `generate_media.py --storyboard-only` output: lightweight coverage plan with `segment_id`, `visual_role`, `scene_type`, narration duration, shot list, model, and risk flags.

Useful current fields:

| Field                                               |           Keep? | Owner                          | Notes                                                                           |
| --------------------------------------------------- | --------------: | ------------------------------ | ------------------------------------------------------------------------------- |
| `project_id`, `beat_id`, `source_script_segment_id` |            Keep | Python                         | Deterministic IDs.                                                              |
| `scene_type`                                        |  Keep but split | LLM proposes, Python validates | Should evolve into `visual_strategy` + `shot_type`; current enum is too coarse. |
| `james_presence`                                    |            Keep | LLM proposes, Python validates | Useful for A-roll ratio and model routing.                                      |
| `duration_target_sec`                               |            Keep | Python derived                 | Initial estimate from words is fine; refine after TTS timing.                   |
| `crop_safety`, `text_policy`, `reference_assets`    |            Keep | Python validates               | Already aligned with constraints.                                               |
| `location_id`, `camera`, `lighting`, `palette`      | Keep but demote | Python defaults + LLM choice   | Useful production constraints, not story logic.                                 |

Missing fields that must be added:

| Missing field group                                                       | Why it matters                                                                      |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `argument_summary`, `viewer_question`, `retention_role`                   | The system must know what the beat is doing, not just what segment number it is.    |
| `why_this_visual`, `narrative_alignment`                                  | Required to stop generic B-roll.                                                    |
| `source_claim_refs`                                                       | Required for evidence visuals and compliance.                                       |
| `storyboard_shots[]`                                                      | Required to separate narrative beat from generated media unit.                      |
| `storyboard_overlays[]`                                                   | Required to make graphics post-production overlays rather than standalone filler.   |
| `overlay timing`, `position`, `style_token`, `animation`, `safe_for_9x16` | Required for actual editing grammar.                                                |
| `approval_state`, `review_state`, `spend_ready`                           | Required to prevent credit spend before approval.                                   |
| `fallback_strategy`, `generation_risk`, `qa_requirements`                 | Required because AI video is unreliable on text, hands, screens, charts, and faces. |

The current constraints file already contains the right philosophy: generated readable text is forbidden, post-production overlay is allowed, and “credits spent before storyboard approved” is an automatic fail. The problem is that the pipeline has not made those concepts first-class objects.

## D. Recommended LLM vs Python split

| Pipeline responsibility       | Owner                                    | Reason                                                                          |
| ----------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------- |
| Narrative beat extraction     | LLM proposes; Python stores/validates    | Requires semantic interpretation.                                               |
| Claim extraction              | LLM proposes; Python links to source IDs | LLM can identify claims; Python must prevent unsupported IDs.                   |
| Source linking                | Python validates; LLM assists            | Source refs must be deterministic and auditable.                                |
| Semantic B-roll selection     | LLM                                      | This is editorial reasoning. Python doing this is how you got `idx % 3 cinema`. |
| Overlay concept design        | LLM                                      | Requires deciding what helps comprehension.                                     |
| Shot prompt writing           | LLM drafts; Python constrains            | Prompt needs visual creativity but must obey rules.                             |
| Negative prompt construction  | Python                                   | Constraint injection should be deterministic.                                   |
| Schema validation             | Python                                   | No negotiation. Invalid JSON should fail loudly.                                |
| Model routing                 | Python                                   | Deterministic based on shot type, risk, audio policy.                           |
| Cost gate                     | Python                                   | Never trust LLM with spend gates.                                               |
| Timing calculation            | Python                                   | TTS/ffprobe/timing map driven.                                                  |
| Audio alignment               | Python                                   | Deterministic media handling.                                                   |
| Overlay rendering             | Python                                   | FFmpeg/renderer execution.                                                      |
| Media generation              | Python                                   | External job orchestration and provenance.                                      |
| Assembly manifest creation    | Python                                   | Contract generation from approved storyboard.                                   |
| Database persistence          | Python                                   | Durable state and migrations.                                                   |
| QA report generation          | Python + LLM reviewer                    | Python measures; LLM evaluates creative fit from frames where useful.           |
| Human feedback ingestion      | Python stores; LLM summarizes            | Store raw feedback; use LLM to turn it into future recommendations.             |
| Performance feedback analysis | Hybrid                                   | Python calculates metrics; LLM proposes creative lessons.                       |

Direct answer: storyboard creation should be **hybrid**, but with a decisive split. The **semantic storyboard content** should be LLM-generated from an elaborate prompt. The **production contract, validation, approval state, routing, timing, paths, rendering, spend gates, and DB persistence** should be Python-owned.

The LLM gets the pen. Python gets the red stamp.

## F. Enhanced process design

| Step                             | Inputs                        | Output                                | Owner                           | Acceptance checks                                                                  |
| -------------------------------- | ----------------------------- | ------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------- |
| 1. Research/source log           | Topic, web/source research    | `research/source_logs/{project}.json` | Human/LLM + Python validator    | ≥3 source records or approved original-source exception.                           |
| 2. Content brief                 | Source log                    | Brief JSON/Markdown                   | LLM                             | Clear promise, audience, evidence, original angle.                                 |
| 3. Claim inventory               | Source log + brief            | `source_claims[]`                     | LLM proposes, Python validates  | Every factual/study/stat/person claim has source ID or is marked original/opinion. |
| 4. Script generation             | Brief + claims                | Script JSON                           | LLM                             | No unsupported claims; segment IDs stable.                                         |
| 5. Script review                 | Script                        | Review report                         | LLM personas + Python aggregate | Hook, retention, brand, audio pass.                                                |
| 6. Narrative beat extraction     | Script + claims               | `narrative_beats[]`                   | LLM + Python                    | Every script segment maps to one or more beats.                                    |
| 7. Storyboard generation         | Beats + constraints + sources | `storyboard_v2.json`                  | LLM                             | Every beat has visual strategy, why, shot refs, overlay refs.                      |
| 8. Creative storyboard pass      | Storyboard draft              | Refined storyboard                    | LLM                             | B-roll specific, overlays purposeful, rhythm intentional.                          |
| 9. Python validator              | Storyboard draft              | Validation report                     | Python                          | Schema, IDs, claims, text safety, crop, model-routing preconditions.               |
| 10. LLM repair loop              | Validation report + draft     | Repaired storyboard                   | LLM + Python loop               | Repeat until valid or fail with precise errors.                                    |
| 11. Storyboard reviewer personas | Valid storyboard              | Creative review report                | LLM personas                    | Narrative alignment, B-roll specificity, overlay relevance, retention rhythm.      |
| 12. Human approval gate          | Valid + reviewed storyboard   | `approval_state=approved`             | Human                           | No media spend before approval.                                                    |
| 13. Overlay plan generation      | Approved storyboard           | Overlay render jobs                   | Python from storyboard          | No standalone graphics unless justified.                                           |
| 14. Media prompt compilation     | Approved storyboard shots     | Media prompt plan                     | Python                          | No raw `visual_brief`; only storyboard shots.                                      |
| 15. TTS/audio timing             | Script/storyboard             | Narration + timing map                | Python                          | Timing map maps beat IDs to audio offsets.                                         |
| 16. Shot timing refinement       | Timing map + storyboard       | Updated shot/overlay timing           | Python                          | Total shot coverage matches narration.                                             |
| 17. Media generation             | Approved media plan           | MP4 assets + jobs                     | Python/external API             | Spend gate, provenance, no banned text surfaces.                                   |
| 18. Overlay rendering            | Overlay jobs                  | PNG/SVG/video overlays                | Python/FFmpeg first             | Text readable, safe for 16:9 and 9:16.                                             |
| 19. Assembly                     | Timeline events               | Final 16:9/9:16 videos                | Python/FFmpeg                   | Overlay timing, audio, crop, volume pass.                                          |
| 20. QA                           | Final videos + frames         | QA report                             | Python + LLM visual reviewer    | Technical + creative QA.                                                           |
| 21. Feedback writeback           | Review/QA/performance         | DB recommendations                    | Python + LLM                    | Future storyboard prompts receive specific lessons.                                |

Targeted web finding: start overlays with FFmpeg because the repo already uses FFmpeg heavily and FFmpeg is officially positioned as a cross-platform video/audio record/convert/stream tool. Use Manim later for complex explanatory diagrams; current research prototypes show LLM-to-Manim workflows can create structured animation code, but they also rely on constrained prompts, regeneration loops, and human/expert review—too much weight for the immediate rescue sprint. ## J. Recommended implementation sequence

### 1. Immediate creative rescue

Build the smallest storyboard v2 path that materially improves the next video:

1. `schemas/storyboard_v2.schema.json`
2. `scripts/generate_storyboard_v2.py`
3. `scripts/validate_storyboard_v2.py`
4. `scripts/review_storyboard_v2.py`
5. `scripts/compile_media_from_storyboard_v2.py`
6. `scripts/production_gate.py`

Do not start with the full database. The next output needs better visual direction, not more tables.

### 2. Schema and validator hardening

Lock semantic fields, ID references, claim refs, overlay specs, text-surface policy, and approval states.

### 3. Overlay/assembly support

Add FFmpeg-based overlays first: key points, source labels, framework steps, comparison panels, simple callout arrows. Save Remotion/Manim for later.

### 4. Database migration

Once JSON storyboard v2 works on one real production, migrate to SQLite as durable SSOT.

### 5. Feedback loop

Only after you have several produced videos should you build analytics correlation. Before that, the “learning loop” is mostly fake precision wearing a lab coat.

## K. Final recommendation

**Keep `storyboard.py`?**
Keep it as legacy/skeleton tooling, but create `storyboard_v2.py` or preferably split modules: `generate_storyboard_v2.py`, `validate_storyboard_v2.py`, `review_storyboard_v2.py`. Do not try to gradually mutate the old deterministic file into the new brain. It is the wrong abstraction.

**Should script JSON still contain `visual_brief`?**
Yes, temporarily, but only as `legacy_visual_brief` or human drafting context. It must not be production-authoritative.

**Should media generation read from script JSON or storyboard JSON/database?**
Storyboard JSON/database only. Script JSON is upstream narrative input. Media generation should consume approved `storyboard_shots` and `media_prompt_plan_v2`.

**Should overlays be rendered by FFmpeg first, or adopt Remotion/Manim immediately?**
FFmpeg first. The existing assembler is already FFmpeg-based, and the immediate need is timed text/labels/callouts/framework overlays. Remotion can wait. Manim is useful later for complex animated diagrams, not the first rescue sprint.

**Minimum sprint that materially improves the next video:**
SB-0002, SB-0005, SB-0008, SB-0009, SB-0010, SB-0016, plus a minimal SB-0007/SB-0011/SB-0012 overlay path. That gives you semantic storyboard → validation → creative review → storyboard-only media prompts → spend gate → basic overlays.

Do not spend another credit on AI video until the storyboard can answer, for every beat: **what is the argument, what should the viewer see, why does that visual help, what overlay reinforces it, and why is this not generic filler?**
