Build a canonical-to-legacy projection module that maps Sonnet-authored canonical shots and overlays into legacy beat-level fields required by existing compiler, DB projection, review, and assembly code.

## Implementation summary

### `scripts/storyboard_projection.py`

Deterministic projection from canonical storyboard shots/overlays to legacy beats:

- `project_canonical(canonical)` — Main entry. Accepts a canonical-mode storyboard, returns `list[dict]` of legacy beats.
- `_project_shot_to_beat(shot, shot_overlays)` — Maps one canonical shot to a beat with all required legacy fields.
- `_overlay_to_graphic(overlay)` — Projects a canonical overlay to a legacy `graphic` dict.

Field mapping is deterministic:

| Legacy field | Canonical source |
|---|---|
| `shot_type` | `visual_role` (direct enum mapping) |
| `asset_type` | Determined from `shot_type` |
| `model` | Determined from `shot_type` + fallback_strategy |
| `prompt_class` | `literal_vs_metaphorical` → descriptive/conceptual/narrative |
| `visual_brief` | `visual_concept` + `prompt_intent` + `must_show` (never raw script) |
| `visual_intent` | `why_this_visual` + `narrative_alignment` + `shot_id` |
| `graphic` / `graphics` | Overlays referencing the shot |
| `reference_required` | True for hero shots, True if `claim_refs` present |
| `text_policy` | Derived from `must_avoid` / `qa_requirements` |

### `tests/test_storyboard_projection.py`

22 tests covering all 7 required behaviors plus edge cases:
1. **Canonical shot → legacy beat fields** (hero_lipsync, broll_metaphorical)
2. **Overlay → graphic/graphics** (single overlay, multiple overlays, unmatched overlay)
3. **ID preservation** (shot IDs, overlay IDs, projection_trace)
4. **Missing semantic source** (why_this_visual, narrative_alignment)
5. **Compiler minimum fields** (presence and legal values for shot_type, segment_id, visual_brief, model, asset_type, prompt_class)
6. **Production storyboard minimum fields** (source_beat_id, segment_id, shot_type)
7. **No raw script visual_brief leak** (verified by data injection test)

## Design decisions

1. **Deterministic mapping tables** — Shot type, model, and asset type use lookup tables in `_VISUAL_ROLE_TO_SHOT_TYPE`, `_MODEL_BY_SHOT_TYPE`, `_ASSET_TYPE_BY_SHOT_TYPE`. No creative logic.
2. **`ProjectionError`** — Raised when a canonical shot lacks `why_this_visual` or `narrative_alignment`. These are required by schema but validated at the application level.
3. **`projection_trace`** — Each beat carries a `projection_trace` dict linking back to its `canonical_shot_id` and `overlay_ids` for full auditability.
4. **`canonical_overlay_id` in graphic** — Each projected graphic dict preserves the originating overlay ID for traceability.
5. **No raw script access** — `_compose_visual_brief` reads only `visual_concept`, `prompt_intent`, and `must_show` from the canonical shot. Confirmed by test that injects a fake `visual_brief` field and verifies it does not leak.

## Non-goals preserved

- No compiler semantics changed
