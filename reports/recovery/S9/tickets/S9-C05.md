## Observable outcome
A beat longer than the model's max clip length is divided into N slots each ≤ max clip length (and ≥ min), with `slot_index`/`slot_total` set and the slot time ranges tiling the span with no gaps/overlaps. Each hero (`HERO_SYNC_LOCKED`) slot has a materialized master-narration audio slice file (and its SHA) linked to the render unit, available for generation `--audio`. Observable by: a unit test that compiles a 30 s hero span and asserts N slots within [min,max], contiguous ranges, and a real (ffmpeg-produced) slice file per hero slot with a verified SHA against the master.

## Implementation steps
1. **Reproduce (failing test first).** Test: compile a 30 s hero span (fixture master mp3) → assert ≥3 slots each within [min,max], contiguous ranges summing to 30 s, and a slice file per hero slot with SHA matching the master subrange. Fails today (1 unit, no slices).
2. **Read clip ranges** from `model_routing.yaml` per shot_type/model; expose them to `invoke_compile_media`.
3. **Compute slots.** In `invoke_compile_media`, for each span, if `duration > max_clip`, split into `ceil(duration/max_clip)` slots of ≤ max (and ≥ min; balance the last slot so none falls below min). Set `slot_index`/`slot_total` and exact `start_ms/end_ms`. Non-long spans remain a single slot (slot_total=1 or None per existing convention).
4. **Materialize hero slices.** For `HERO_SYNC_LOCKED` slots, slice the master narration (`assets/.../continuous.mp3` or the `tts_master` artifact) by the slot's [start,end] via ffmpeg, register each slice as an artifact (kind `hero_audio_slice`), SHA-verify it, and attach `master_audio_artifact_id` + `speech_start_sample/end_sample` to the slot spec.
5. **Persist via `plan_render_units`** (confirm it threads sample ranges + slice ref into the unit row).
6. **Contiguity invariant.** Add a unit test asserting slots tile the span exactly (sum of slot durations == span duration; no overlap).
7. **Negative/boundary:** span exactly == max → 1 slot; span == max+1 → 2 slots; a tiny span < min → defined behavior (clamp to 1 slot or fail-loud per policy; document).
